# 30 天把 Threads 变成可验证的获客实验

这份计划的目标是验证一条交易路径：**提供价值 → 获得自愿联系 → 确认需求 → 合法收款 → 交付 → 复盘**。每天的工作在没有用户实际反馈时可以跳过、延后或停止；并非“30 天收入承诺”。

| 天数 | 最重要的动作 | 当天应留下的产物 | 最终判断 |
|---|---|---|---|
| D1 | 列出 3 项已有技能，选择一个真实客户问题 | 问题、付款人、可交付件各一句 | 能解释为什么有人付费 |
| D2 | 手动看 15 条垂直讨论，摘录真实需求原话 | 需求表，去除个人信息 | 是否重复出现同一类问题 |
| D3 | 写清价格、服务范围、排除项和退款安排 | 一张服务卡 | 客户能否独立理解 |
| D4 | 完成头像简介、主页链接、作品证明 | 主页截图（脱敏） | 访问者 5 秒理解 |
| D5 | 发布经历帖：做过的事、遇到的错误、具体改动 | 第一条原创帖子链接 | 是否收到目标问题 |
| D6 | 发布方法帖：一个步骤、适用前提与失败边界 | 一条步骤帖 | 是否真正可照做 |
| D7 | 复盘首周内容、互动、主页与链接数据 | 周复盘 1 | 若全是泛流量，则换内容角度 |
| D8 | 针对 1 个高频问题写 FAQ | FAQ 帖 | 评论是否提出更细问题 |
| D9 | 有意义地回复专业讨论，先提供方法 | 3 条有价值的回复链接 | 对方是否自愿继续交流 |
| D10 | 发布一条脱敏流程展示，附真实产物 | 流程/作品帖 | 是否提高信任信号 |
| D11 | 做一份真正免费的样例材料 | 开源清单或样例 | 能否帮助陌生人 |
| D12 | 检查移动端落地页、隐私说明、链接 | 点击体验记录 | 任何必需步骤是否失效 |
| D13 | 正式介绍服务适合谁、不适合谁 | 产品说明帖 | 客户是否知道价格和交付 |
| D14 | 复盘第 2 周，用实际询盘判断方向 | 周复盘 2 | 优先识别主流失步骤 |
| D15 | 把目标问题拆成系列帖第 1 篇 | 专项长帖 | 是否有深度回复 |
| D16 | 同主题用反例补充边界 | 反例帖 | 是否减少误解 |
| D17 | 为真实自主咨询设计两问筛选 | 问诊话术 | 是否能确定需求适配 |
| D18 | 整理合同/付款/发票/交付提醒 | 合规检查清单 | 真实付款是否具备条件 |
| D19 | 发布一次工具实测/方案比较 | 测试记录（不夸大） | 是否有可核验材料 |
| D20 | 整理客户反馈，未经同意不发布内容 | 匿名内部观察表 | 重复出现哪个疑虑 |
| D21 | 复盘第 3 周转化漏斗 | 周复盘 3 | 有无报价？哪一步卡住？ |
| D22 | 无点击则改主页表述，勿同时改多个变量 | A/B 变更记录 | 小样本仅作方向性参考 |
| D23 | 有点击无询盘则改落地页、FAQ、服务边界 | 简化服务页 | 用户是否更易做决策 |
| D24 | 有询盘无付款则检查产品匹配、价格和证据 | 未成交原因清单 | 区分客户拒绝与无需求 |
| D25 | 有付款则整理实际工作量和交付质量 | 项目交付核对 | 是否可盈利且可持续 |
| D26 | 发布真实复盘：数据口径、尝试、失败 | 过程帖 | 是否提高高质量互动 |
| D27 | 测试另一种内容角度（同一个产品） | 实验样本 | 哪个角度带来更多有效询盘 |
| D28 | 复盘第 4 周实收、退款与交付工时 | 收益与工时台账 | 贡献毛利能否为正 |
| D29 | 给下一阶段设停止条件 | 决策阈值 | 何时停止浪费注意力 |
| D30 | 写一页最终结果和下次单一变量实验 | 30 天实验报告 | 继续、调整、转移渠道或暂停 |

## 判定与停止

- 连续两周没有目标受众的实际提问：重新检查目标人群、内容是否只吸引泛流量。
- 有精准访问、没有有效咨询：检查服务说明、可信证据、联系方式与隐私门槛。
- 有询盘、没有收款：检查问题强度、交付范围、定价与支付渠道。别上来硬降价。
- 有付款但毛利或客户体验很差：立刻降低复杂度、缩紧范围，暂停扩大曝光。
- 出现平台违规提示：停止可疑操作，检查规则与内容，不尝试规避风控。
