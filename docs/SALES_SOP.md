# Threads 客户转化与交付 SOP

## 合规流程

**目标：** 客户自愿联系，双方明确需求和服务责任；不搞群发骚扰。 

1. **触达：** 发布有实操价值的内容，在公开讨论中回答真实问题，个人主页列明免费资源与服务说明。
2. **第一条私信：** “你现在主要卡在【具体问题】，对吧？我先确认两个点，判断是否适合帮你。”
3. **两问筛选：** 当前目标是什么？已经试过哪些方案？如果需要补充，可在对方同意下询问时间预算。
4. **资格判断：** 对方需求是否在自己擅长领域？必要数据是否能合法提供？是否存在过度承诺？
5. **报价：** 交付项、范围、时间、价格、修改次数、退款、数据使用、付款主体。不得仅写“包会/保过”。
6. **收款：** 确认正规收款信息，提供合同/订单记录与实际交付安排。
7. **交付：** 收取必要资料、按承诺执行、交付可验证产物、保留双方认可的变更记录。
8. **结束：** 记录客观反馈、净贡献和后续事项。客户拒绝案例使用即不公开。

## 需求诊断卡

| 字段 | 例子（仅为模板） |
|---|---|
| 客户要解决的问题 | 【目标岗位简历无法获得反馈】 |
| 已知事实 | 【投递岗位与反馈数量，客户自述】 |
| 待核假设 | 【简历表达、投递方向、样本不足】 |
| 服务适配 | 【适合/不适合，原因】 |
| 必须交付的文件/结果 | 【简历修改稿与建议清单】 |
| 范围外事项 | 【不承诺拿到 Offer】 |
| 价格、时长、退款 | 【按自己的真实报价】 |
| 隐私与授权 | 【仅在客户同意下处理资料】 |

## 交付验收清单

- [ ] 付款/签约主体与交付责任一致。
- [ ] 服务范围、修改次数及交付时间已约定。
- [ ] 客户材料有授权、用途与保留期限说明。
- [ ] 交付文件能打开且与报价描述一致。
- [ ] 风险、限制、剩余行动清楚可见。
- [ ] 退款/争议有明确处理路径。
- [ ] 不发布未经客户同意的聊天截图或具体资料。

## 重点反对意见

- **“你能保证结果吗？”** ——“不能保证最终录用/收入。我保证按约定完成【可验收服务】，并说明风险。”
- **“为什么这个价格？”** ——“费用对应【工作范围与交付工时】。你也可以先用我公开的免费材料判断是否需要服务。”
- **“能先免费帮我做完吗？”** ——“可以先看免费样例，付费部分的边界和交付我都写在说明页里。”
- **“加你微信之后会被营销吗？”** ——“只在你主动提出需求时沟通，拒绝后不再追发。”
